# 52주 신고가 전략 모델 1~4 설명

## 요약

이 문서는 한국 주식 유니버스를 대상으로 한 52주 신고가 돌파 전략 4개를 설명한다. 네 모델은 모두 롱 온리 전략이며, 공통적으로 52주 신고가 돌파 신호, 시장 지수 이동평균 필터, -8% 손절, +24% 반익절, 신규 진입 시 종목당 15% 비중 제한을 사용한다.

최종 문서와 성과 비교 차트에서는 모델명을 아래처럼 표시한다. 코드 내부 모델명은 변경하지 않았다.

| 표시명 | 전략 요약 |
|---|---|
| 모델 1 | 52주 신고가 돌파 + 시장 지수 필터 + 동일비중 |
| 모델 2 | 52주 신고가 돌파 + L/I 조건 + 시장 지수 필터 + 매크로 rank 비중 |
| 모델 3 | 52주 신고가 돌파 + 시장 지수 필터 + 매크로 rank 비중 |
| 모델 4 | 52주 신고가 돌파 + L/I 조건 + 시장 지수 필터 + 동일비중 |

백테스트 평가 기간은 워밍업 이후인 **2013-01-02 ~ 2026-06-01**이며, 초기 자본은 **100,000,000원**이다.

## 사용 데이터

백테스트는 전처리된 한국 주식, 시장 지수, 기관 수급, 매크로 데이터를 사용한다.

| 데이터 | 사용 목적 |
|---|---|
| 종목 시가/고가/저가/종가 | 52주 신고가 돌파, 체결가, 손절/익절, 평가금액 계산 |
| 종목 거래량 | feature 호환용 데이터. 모델 1~4의 진입 조건에는 직접 사용하지 않음 |
| 기관 순매수 | 모델 2와 모델 4의 `I` 조건 계산 |
| 시가총액 | 기관 순매수 금액 정규화 |
| KOSPI/KOSDAQ 지수 | 시장 이동평균 필터 및 벤치마크 계산 |
| 매크로 채널 상태와 섹터 exposure | 모델 2와 모델 3의 매크로 rank 비중 계산 |
| 종목 메타데이터와 유니버스 | 티커, 시장, 섹터 매핑 |

최근 실행 기준 로드된 유니버스는 **2,317개 종목**, 일봉 데이터는 **4,040개 거래일**이다.

## 진입 조건

### 공통 52주 신고가 돌파

각 종목별로 직전 252거래일 고가의 최댓값을 52주 신고가 기준으로 사용한다. 당일 고가는 기준값 계산에 포함하지 않는다.

```text
high52_prev[t] = max(high[t-252], ..., high[t-1])
close_breakout[t] = close[t] > high52_prev[t]
open_breakout[t+1] = open[t+1] > high52_prev[t+1]
```

진입은 아래 둘 중 하나가 참이면 가능하다.

- `t일 종가`가 52주 신고가를 돌파하면 `t+1일 시가`에 매수
- `t+1일 시가`가 52주 신고가를 돌파하면 `t+1일 시가`에 매수

진입 신호는 신규 매수에만 적용한다. 이미 보유 중인 종목은 이후 신규 진입 필터가 꺼져도 강제 청산하지 않는다.

### L 조건

`L`은 상대강도와 주도주 여부를 보는 조건이다. 모델 2와 모델 4에만 적용한다.

```text
RS percentile = 전체 유니버스 내 252일 수익률 percentile rank
RS line = 종목 종가 / 해당 시장 지수 종가
RS slope = RS line의 63일 rolling slope

L 통과 조건:
RS percentile >= 90
and RS slope > 0
```

KOSPI 종목은 KOSPI 지수를, KOSDAQ 종목은 KOSDAQ 지수를 비교 지수로 사용한다.

### I 조건

`I`는 기관 수급 증가 여부를 보는 조건이다. 모델 2와 모델 4에만 적용한다.

```text
institution_flow = 기관 순매수 금액 / 시가총액
inst_flow63 = institution_flow의 63일 rolling sum
cum_flow126 = institution_flow의 126일 rolling sum
inst_beta = cum_flow126의 63일 rolling slope

I 통과 조건:
inst_flow63 > 0
and inst_beta > 0
```

### KOSPI/KOSDAQ 이동평균 필터

네 모델 모두 시장별 이동평균 필터를 사용한다.

| 종목 시장 | 신규 진입 필터 |
|---|---|
| KOSPI | KOSPI 지수 종가 >= KOSPI 200일 이동평균 |
| KOSDAQ | KOSDAQ 지수 종가 >= KOSDAQ 120일 이동평균 |

이 필터는 신규 진입에만 적용한다. 보유 중에는 지수가 이동평균선 아래로 내려가도 이 조건만으로 청산하지 않는다.

## 매크로 Rank 계산법

모델 2와 모델 3은 매크로 rank를 신규 후보의 비중 계산에 사용한다. 현재 백테스트에서 사용하는 매크로 점수는 DART 공시 점수를 결합한 최종 종목 점수가 아니라, **Stage 1의 종목별 매크로 섹터 점수**다.

### 매크로 채널

매크로 채널은 다섯 개다.

| 채널 | 의미 | 대표 지표 |
|---|---|---|
| `G` | Growth / Activity | 한국·미국 산업생산 YoY 3개월 평균 |
| `IC` | Inflation / Cost | 한국·미국 CPI YoY 3개월 평균 |
| `FC` | Financial Conditions | 한국·미국 신용스프레드 z-score |
| `ED` | External Demand | 한국 대미 수출 YoY 3개월 평균, 미국 실질 재화수입 YoY 3개월 평균 |
| `FX` | Foreign Exchange | USD/KRW 3개월 로그수익률, broad USD 3개월 로그수익률 |

각 지표는 cutoff 기준으로 `-1`, `0`, `+1` 상태로 분류된다.

| 지표 | positive cutoff | negative cutoff | positive 방향 |
|---|---:|---:|---|
| 한국 산업생산 YoY 3개월 평균 | 1.0 | -1.0 | 높을수록 긍정 |
| 미국 산업생산 YoY 3개월 평균 | 1.0 | -1.0 | 높을수록 긍정 |
| 한국 CPI YoY 3개월 평균 | 2.75 | 1.25 | 높을수록 긍정 |
| 미국 CPI YoY 3개월 평균 | 2.75 | 1.25 | 높을수록 긍정 |
| 한국 신용스프레드 z-score | -0.5 | 0.5 | 낮을수록 긍정 |
| 미국 신용스프레드 z-score | -0.5 | 0.5 | 낮을수록 긍정 |
| 한국 대미 수출 YoY 3개월 평균 | 2.0 | -2.0 | 높을수록 긍정 |
| 미국 실질 재화수입 YoY 3개월 평균 | 1.5 | -1.5 | 높을수록 긍정 |
| USD/KRW 3개월 로그수익률 | 2.5 | -2.5 | 높을수록 긍정 |
| broad USD 3개월 로그수익률 | 2.0 | -2.0 | 높을수록 긍정 |

같은 채널에 속한 지표 상태값을 산술평균한 뒤 neutral band와 비교해 최종 채널 상태를 정한다.

```text
combined_score[channel] = average(signal_state for indicators in channel)

channel_state = +1 if combined_score > neutral_band
channel_state =  0 if -neutral_band <= combined_score <= neutral_band
channel_state = -1 if combined_score < -neutral_band
```

neutral band는 다음과 같다.

| 채널 | neutral band |
|---|---:|
| `G` | 0.25 |
| `IC` | 0.25 |
| `FC` | 0.25 |
| `ED` | 0.25 |
| `FX` | 0.50 |

### 종목별 매크로 섹터 점수

각 grouped sector는 다섯 개 매크로 채널에 대한 exposure 값을 가진다. 섹터 매크로 점수는 채널 상태와 섹터 exposure를 곱한 값을 모두 합산해서 계산한다.

```text
channel_contribution[channel] = channel_state[channel] * sector_exposure[channel]
sector_macro_score = Σ channel_contribution[channel]
```

각 종목은 grouped sector에 매핑되고, 해당 섹터의 `sector_macro_score`를 종목별 macro score로 사용한다. 따라서 같은 grouped sector에 속한 종목은 같은 매크로 점수를 받는다.

### Rank 비중 변환

매일 신규 후보 종목을 macro score 기준으로 rank한다. 매크로 점수가 높을수록 높은 rank와 높은 비중을 받는다.

```text
rank = rank(macro_score, ascending=True)
raw_weight = rank / sum(rank)
```

이후 신규 진입 종목당 15% cap을 적용한다. cap에 걸린 종목이 있으면 남는 비중은 아직 cap에 걸리지 않은 후보에게 재분배한다. 모든 후보가 cap에 걸리면 남은 현금은 현금으로 유지한다.

## 비중 조건

| 모델 | 비중 방식 | L/I 조건 |
|---|---|---|
| 모델 1 | 동일비중 | 미사용 |
| 모델 2 | 매크로 rank 비중 | 사용 |
| 모델 3 | 매크로 rank 비중 | 미사용 |
| 모델 4 | 동일비중 | 사용 |

동일비중 모델은 신규 진입 가능한 후보를 같은 비중으로 배분한다.

```text
raw_weight = 1 / 신규 후보 수
```

모든 모델은 신규 진입 주문에 종목당 15% cap을 적용한다.

```text
max_new_position_value = 신호일 기준 포트폴리오 평가금액 * 15%
order_value = min(현금 예산 * capped_weight, max_new_position_value)
```

15% cap은 신규 진입 시점에만 적용한다. 보유 중인 종목이 상승해서 전체 포트폴리오의 15%를 넘더라도 강제로 줄이지 않는다.

## 익절/청산 조건

### 손절

종가 기준 수익률이 진입가 대비 -8% 이하이면 전량 청산한다.

```text
close[t] / entry_price - 1 <= -8%
```

청산은 `t+1일 시가`에 체결된다.

### 반익절

종가 기준 수익률이 진입가 대비 +24% 이상이고, 아직 반익절을 한 적이 없으면 보유 수량의 절반을 매도한다.

```text
close[t] / entry_price - 1 >= 24%
```

반익절은 `t일 종가`에 체결되며, 포지션당 1회만 발생한다.

### 반익절 후 잔여 수량 청산

반익절 이후 남은 수량은 아래 조건 중 하나가 참이면 전량 청산한다.

```text
close[t] <= 10일 이동평균
or close[t] <= 반익절 가격
```

이 청산은 `t+1일 시가`에 체결된다. 여기서 반익절 가격은 +24% 조건으로 절반을 매도했던 당일 종가다.

### 상장폐지 또는 미래 가격 없음

보유 종목에 대해 더 이상 미래의 시가 또는 종가 데이터가 없으면 해당 잔여 포지션은 `0원`으로 매도 처리한다. 즉, 상장폐지 또는 거래 불가능 상태를 -100% 손실로 반영한다.

## 결론

네 모델 중 전체 성과가 가장 좋은 전략은 **모델 1**이다. 모델 1은 동일비중을 사용하면서 L/I 필터 없이 넓은 52주 신고가 후보군을 활용한다. KOSPI 200일선과 KOSDAQ 120일선 필터가 약한 시장 구간의 신규 진입을 제한해, KOSPI/KOSDAQ 50:50보다 높은 누적수익률과 훨씬 낮은 MDD를 기록했다.

**모델 3**은 모델 1에 매크로 rank 비중을 적용한 버전이다. 성과는 모델 1보다 약간 낮다. 이번 백테스트에서는 매크로 rank 비중이 넓은 52주 신고가 후보군에서 동일비중보다 우월하지 않았다.

**모델 2**와 **모델 4**는 L/I 조건을 추가한 더 선별적인 전략이다. 두 모델은 거래 수가 크게 줄고 MDD도 낮지만, 누적수익률과 CAGR은 모델 1/3보다 낮다. L/I 필터가 방어력에는 도움이 되었지만, 강한 상승장에서 일부 신고가 주도 종목을 놓치며 수익률을 낮춘 것으로 해석된다.

동일한 진입 필터 안에서는 이번 결과 기준으로 **동일비중이 매크로 rank 비중보다 더 나았다**. 다만 매크로 rank는 섹터 국면을 반영하는 장점이 있으므로, 향후에는 rank 비중 자체보다 매크로 점수를 진입 허용/차단 필터로 쓰는 방식도 별도 테스트할 가치가 있다.
